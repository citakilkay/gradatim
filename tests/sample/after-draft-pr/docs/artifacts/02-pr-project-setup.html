A SvelteKit app that passes the gate and deploys to Cloudflare Pages

This sets up the project every later task builds on: a static SvelteKit app in TypeScript, its tests, a gate on each pull request, and Pages previews and production. It comes first because every story in sprint 1 needs a project that builds.

Opened 2026-11-10 Tasks OPS-1 Stories the MVP (setup) Branch ops-1-project-setup into main

What it aims at

Once this is merged, any branch can open a pull request that runs the full gate in GitHub Actions and gets a Cloudflare Pages preview, and a merge to main deploys to production. A reader sees only a placeholder page for now.

  • OPS-1Project setup and Cloudflare Pages the SvelteKit project, the npm scripts, the tests, the Actions gate and the Pages deploy, for the MVP

What it changes

  • changedBuild SvelteKit 3 with the static adapter writes plain files to build/. The config sits in vite.config.ts, since kit 3 refuses svelte.config.js. Node 24 is pinned in .nvmrc.
  • changedTests Vitest with jsdom and Testing Library holds a unit test and a component test. Playwright holds one test, run against the production build served by vite preview.
  • changedThe gate .github/workflows/gate.yml, job gate, runs check, test, test:e2e and build on each pull request and push to main. Pages' own build runs check, test and build.
  • changedDeploy npm run deploy runs wrangler pages deploy build --project-name shelf for a deploy by hand. No Cloudflare token is stored in GitHub.
  • affectedDocs docs/agents/commands.md, docs/RUNBOOK.md, docs/ARCHITECTURE.md and docs/agents/development-cycle.md now say the gate is split between Actions and Pages.

Before and after

Before

The repository holds only the plan and its documents. Nothing builds, tests or deploys.

After

A placeholder page builds static, passes four commands, and deploys: each pull request to a Pages preview, and main to production.

What to check

  1. Start with package.json and vite.config.tsThe scripts match docs/agents/commands.md, and #lib imports go through package.json's imports, since kit 3 dropped $lib.
  2. Run npm ci, then npm run check, npm test, npm run test:e2e and npm run buildAt the close: check with 0 errors, test with 2 passed, test:e2e with CI set with 1 passed, and build/ written.
  3. Look at the gate job on this pull requestIt should pass. It passed on the earlier test pull request, on the user's word.
  4. Open the Pages preview addressIt serves the placeholder page with its heading. The user saw this on the test pull request.

Risks

The gate job blocks nothing until it is required in main's branch protection, which the user sets. Pages' v3 image must install Node 24 from .nvmrc, or the build sets NODE_VERSION. The job builds twice, once in Playwright's web server and once in its last step: the review left this, since it does no harm. A new repository's first setup is easy to undo: nothing in it holds data.
