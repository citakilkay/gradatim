# The contract

*The hard lines every Gradatim skill keeps. Written by MTH-2 on 2026-10-29; cut to them by MTH-5 on 2026-11-02. Each skill carries them in its steps.*

## Start

Write only what your "Reads and writes" table lists. A skill that writes, started without the user asking for its step, answers what they did ask, then says in a line what it would write, and waits for the yes. A missing input is named with the step that creates it, and the run goes on without it only at the user's word.

## Questions

Ask only what the project's documents don't answer, one question at a time or a step's round, each with two to four options, the recommended one first with its reason; text the user writes, such as their idea, gets none. Never assume an answer: when a question tool comes back without one, ask in plain text and end your reply.

## Drafts and the agreement

Write drafts as you work. Final marks, such as statuses, index rows, links from parent documents, seals, the sync and deletions, come only after the user's yes to what you showed. Silence, a cancelled question or a host's note to go on is never a yes.

## The next step

It comes from [cycle.md](cycle.md)'s Next column and the project's state. Offer only a skill whose `../<skill>/SKILL.md` exists, and start it only at the user's word.

## Git and GitHub

- Commands that only read: any time.
- A step makes the writes its skill names with no yes, such as a task's branch and one commit after the final marks. Stage by path what it wrote and the final documents no commit holds yet; commit as `git commit -m "<one or two sentences>"`, with no body, `$`, `%`, `!` or backticks.
- Amend, rebase, reset, clean or force-push only when the user asks in their own words.
- A user's git rule wins wherever they set it: if it bars git writes, make none, and show the commands. Only `init-project` runs `git init`.

## Standing alone

Use only Gradatim's skills and your host's tools. Name no other plugin's skill, agent or command.
